evidencias del backend (go)
===========================
fecha: 2026-11-17 · go 1.27.4 · postgresql 18

hay tres formas de correr el backend (y una cuarta: en la nube), y todas pasan las mismas pruebas
(scripts/probar_backend.sh: todo entra por el gateway, como un navegador):

  1. local: 6 instancias de postgresql como procesos + 7 programas (scripts/backend.sh)
  2. docker: docker-compose.yml (6 postgres + init + 7 contenedores) -> 30/30 el 2026-11-16,
     antes de agregar la prueba del bloqueo de login
  3. docker contra neon: docker-compose.neon.yml (7 contenedores, las bases en neon) -> 31/31
  4. en la nube: la misma docker-compose.neon.yml en una vm de azure -> 31/31

el pedido de prueba sale con otro numero en cada ambiente (cada base lleva su propia cuenta).


1. pruebas de go (cd backend && go test -count=1 ./...)
--------------------------------------------------------
ok  	github.com/iYeremy/bd-multisede-microservicios/backend/internal/gateway	0.009s
ok  	github.com/iYeremy/bd-multisede-microservicios/backend/internal/plataforma	0.006s
ok  	github.com/iYeremy/bd-multisede-microservicios/backend/internal/servicios/identidad	0.060s
ok  	github.com/iYeremy/bd-multisede-microservicios/backend/internal/servicios/ventas	0.006s

  gateway:     borra los X-Usuario-* falsos y nunca reenvia /interno
  plataforma:  ConRol, SedeDe, y que ningun servicio importe el codigo de otro
  identidad:   md5 -> bcrypt, sesiones que vencen, bloqueo tras 5 claves malas
  ventas:      validacion de un pedido nuevo

3. que pasa si se cae catalogo (local, scripts/backend.sh detener catalogo)
---------------------------------------------------------------------------
$ curl localhost:8080/salud
{"servicios":[{"servicio":"catalogo","estado":"caido","ms":0},{"servicio":"identidad","estado":"ok","ms":1},{"servicio":"compras","estado":"ok","ms":0},{"servicio":"inventarios","estado":"ok","ms":0},{"servicio":"ventas","estado":"ok","ms":0},{"servicio":"reportes","estado":"ok","ms":1}]}

$ (como vendedor_cali) POST /api/ventas/pedidos
{"error":"Catalogo no disponible: no se creo el pedido"}  -> 503

$ (como vendedor_cali) GET /api/ventas/pedidos
{"aviso":"Catalogo no responde: se muestran los ids de cliente sin nombre","catalogo_disponible":false,"filas":71,"fragmento":"ventas.ped_cali", ...}  -> 200

ventas sigue funcionando para leer; solo no puede crear pedidos, porque sin
catalogo no puede validar el cliente ni sacar los precios.

contra neon cada consulta tarda ~200 ms (ida y vuelta a la region de neon),
contra ~1 ms en local. si un proyecto de neon estaba dormido, la primera
consulta tarda unos segundos mas mientras despierta.
